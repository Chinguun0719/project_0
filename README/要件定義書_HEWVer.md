## 2. プロジェクト概要

### 2.1 テーマ

HEW Crypto Market ―模擬暗号資産投資体験―

### 2.2 概要

来場者が1,000 HEWCoinを使って3種類のトークンを売買し、市場の価格変動を体験する展示型の模擬投資体験。

### 2.3 背景

投資や暗号資産への関心は高まっているが、実際に投資を体験する機会は少ない。本物の金融資産やお金を扱う展示は重大な法規制・安全面のリスクを伴うため、学校展示には適さない。そこで、会場内で完結する模擬市場「HEWCoin」を提案する。これにより、来場者は取引を通じて資産の価値がどのように増減するかを安全に体験できる。

### 2.4 目的

本プロジェクトの目的は、来場者が短時間で、模擬取引を通じて資産の価値がどのように増減するかを体験できるようにすることである。

### 2.5 対応プラットフォーム

Webブラウザ（学内ネットワークからのみアクセス可能で、学外には公開しない）

## 3. 用語集

| 用語 | 説明 |
|---|---|
| HEWCoin | 展示内でのみ使用する模擬通貨。来場者は最初に1,000 HEWCoinを受け取る。HEWCoinは現金と交換できない。 |
| トークン | 来場者が取引する模擬資産。GAME、CG、WEBの3種類がある。 |
| 流動性 | 各トークンに設定される値。流動性が高いほど、同じ取引額による価格変動は小さくなる。 |
| 変動係数 | トークンの価格変動の度合いを調整する係数。 |
| 変動率 | 1回の取引後にトークンの価格が変化する割合。取引額・流動性・変動係数に基づいて算出される。 |
| 総資産 | 来場者のHEWCoin残高と、保有する全トークンの現在の価値（保有量×現在の価格）の合計。 |

## 5. 機能要件

### 5-1. Version 1.0 対象機能（スコープイン）

| # | 機能 | 説明（何ができるか） | 優先度 |
|---|---|---|---|
| 1 | 初期HEWCoin付与 | 新規登録した各来場者に1,000 HEWCoinを付与する。 | 高 |
| 2 | トークン売買 | 来場者はGAME、CG、WEBから選び、100、300、500 HEWCoin単位でトークンを売買できる。トークンの価格は取引が完了するたびに更新される。 | 高 |
| 3 | 資産概要 | 来場者のHEWCoin残高、保有トークン、総資産額を確認する。 | 中 |
| 4 | ランキング表示 | 来場者の総資産額に基づくリアルタイムランキングを表示する。 | 中 |
| 5 | 追加HEWCoin付与 | 残高が不足し取引を続けられない来場者に、追加でHEWCoinを付与する。実際の金銭のやり取りは発生しない。 | 低 |
| 6 | マイページ | 来場者のニックネーム、保有トークン、口座残高、取引履歴を確認する。 | 高 |
| 7 | 登録画面 | 来場者はニックネームを登録して仮の展示用アカウントを作成する。資産と取引履歴は、複数日にわたる来場でも保持される。 | 高 |
| 8 | 市場一覧 | 各トークンの現在価格と直近の値動きを確認する。 | 中 |
| 9 | 最終ランキング発表 | 最終日に市場をクローズし、最終的な総資産額を算出してランキングを確定し、結果を発表する。 | 高 |

### 5-2. Version 1.0 対象外機能（スコープアウト）

| # | 機能 | 除外理由 |
|---|---|---|
| 1 | チャット | 来場者同士のコミュニケーション機能は、チームが売買体験に集中できるようVersion 1.0では対象外とする。 |
| 2 | ニュース | 価格変動の要因を説明・演出するニュースフィードは体験を向上させる可能性があるが、実装コストを考慮しVersion 1.0では対象外とする。 |
| 3 | 市場リセット | 市場は2〜3日間の展示期間を通じて継続的に稼働し、最終日にクローズする。そのため市場リセット機能は不要である。 |
| 4 | 本人確認・アカウント認証 | ニックネームのみによる登録のみを実装する。メール認証、本人確認、本格的なアカウント管理は含まない。 |

## 6. 非機能要件

| # | 区分 | 内容 |
|---|---|---|
| 1 | 公開範囲 | 本システムは学内ネットワーク内でのみ公開し、学外へは一般公開しない。 |
| 2 | セキュリティ | 本システムは必要最小限のユーザー情報のみを収集する。アクセスは学内ネットワークに制限する。 |
| 3 | 応答速度 | 複数の来場者が同時にアクセスした場合でも、操作から画面への反映は数秒以内に行う。 |
| 4 | 可用性 | 展示期間中、本システムは継続的かつ安定的に稼働する。1人の来場者の操作によるエラーが、他の来場者に影響してはならない。 |
| 5 | ユーザビリティ | 暗号資産や投資の知識がない来場者でも、直感的で分かりやすいUIとする。 |

## 7. 制約条件・前提条件

- 開催期間は2〜3日間。この期間中は市場をリセットせず、最終日に停止して最終ランキングを発表する。
- 本システムは学内ネットワーク内でのみ公開し、学外へは一般公開しない。
- 来場者はニックネームを登録し、各自のスマートフォンからサービスを利用する。
- 開発・運用は5名のチームで行う。

## 9. リスク・課題

| # | リスク・課題 | 対応方針 |
|---|---|---|
| 1 | 学内Wi-Fiは同時接続数や利用可能な帯域に制限がある可能性がある。 | 通信量を最小限に抑え、事前に同時アクセス・負荷テストを行う。 |
| 2 | 開発期間が短く、5人チームで実装できる機能量には限りがある。 | Version 1.0のスコープを絞り込み（5章参照）、優先度の低い機能は後回しにする。 |
| 3 | 展示当日に来場者が集中し、運用上のボトルネックが発生する可能性がある。 | 来場者数の見込みを立て、明確な運用手順を用意し、想定同時利用者数に基づいた負荷テストを行う。 |
| 4 | メンバー間のスキルの偏りにより、担当領域ごとに進捗差が出る可能性がある。 | 定期的な進捗共有ミーティングを行い、技術的な知見を共有し、必要に応じてタスクを再配分する。 |
